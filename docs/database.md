# BoraMatch database contract

All calls use `supabase.rpc(name, args)` with a signed-in, non-anonymous user. Results are JSON, not JSON strings. SQL errors roll back the entire call; the API should map permission errors to 403, validation to 400 and quota conflicts to 429. Never expose service credentials.

## Profile

`complete_onboarding({p_profile})`: required keys `display_name` (2–60 chars), `city_id` (slug), `consent:true`. DOB comes from `auth.users.raw_user_meta_data.dob` (ISO date; at least 18); if supplied in the payload it must match. Optional: `gender` (`man|woman|nonbinary|unspecified`, default `unspecified`), `looking_for` (nonempty array of those values, defaults to all four), `relationship_goal` (≤100 chars), `bio` (≤500), `interests` (≤20 strings), `min_age` (18), `max_age` (99), `max_distance_km` (100), `city_only` (false). Consent records the server's current policy version. DOB cannot subsequently change. `update_profile({p_profile})` patches the same fields except DOB and consent. `my_profile()` returns `{id,display_name,gender,looking_for,city_id,bio,relationship_goal,interests,min_age,max_age,max_distance_km,city_only,age,photos,plan,status,boost_until,created_at}` or null before onboarding. No RPC exposes another user's DOB. `photos` is an array of `{slot,path}`. Paths require signed Storage URLs.

## Discovery and interactions

`discover({p_limit:20,p_city:null,p_min_age:null,p_max_age:null,p_interest:null,p_max_distance:null,p_gender:null,p_filters:{}})` → array (maximum 50) of `{id,display_name,age,gender,city_id,city_name,bio,relationship_goal,interests,distance_km,photos}`. `p_filters` accepts `{city,min_age,max_age,interest,max_distance,gender}`; legacy named optional filters remain supported and take precedence. All optional filters narrow persisted mutual preferences BEFORE the result limit. City is a slug; interest is one string; distance is kilometers; gender uses the enum above. Distance uses city centroids only. Both users' gender, age, city/distance and nonempty interest filters apply. Excludes either-direction blocks, prior decisions, inactive accounts and existing matches. Boosts rank first, then count of shared interests, creation time, ID. Cards include `shared_interests` (sorted intersection of self-declared interests); this is an observable overlap only, not a psychological score. No exact coordinates are accepted or stored.

`decide({p_target,p_action})` where action is `like|pass|superlike` → `{decision_id,target_id,action,matched,match_id}`. Targets must currently be eligible; repeat decisions fail. Daily quotas serialize on the account row. UTC day quota usage remains spent after rewinds. Reciprocal likes create one canonical match atomically. `rewind()` → `{target_id}`; Plus/Gold only, latest decision only, cannot undo a match. `boost()` → `{boost_until}`; Gold only, quota per UTC month. `who_liked_me()` → card array; Gold only, active unblocked mutually eligible users who liked you, excluding your decisions.

`list_matches()` → `[{id,created_at,peer:<card>,last_message:{id,sender_id,body,created_at}|null,unread_count,peer_read_at}]`. `get_messages({p_match,p_before:null})` → up to 100 messages oldest-first from the latest page: `[{id,match_id,sender_id,body,created_at}]`. To load older pages pass the oldest `created_at`. `send_message({p_match,p_body})` → message object; only active unblocked match participants, 1–2000 trimmed characters, at most 20 messages/minute and 500/day per sender. `mark_read({p_match})` → `{read_at}`; read cursor is server time. `unmatch({p_match})` → `{ok:true}`; permanent termination, retained decisions prevent rediscovery.

`block_user({p_target})` → `{ok:true}`; ends matches and denies chat/photo access in both directions. `report_user({p_target,p_reason,p_details:''})` → `{report_id}`; reason `spam|harassment|inappropriate|underage|scam|other`; reports also block. Reports are visible only to reporter; moderation roles access reports through `admin_reports()`.

## Photos

`reserve_photo({p_slot,p_extension})` → `{path,bucket:'profile-photos'}`. Slot 1–9; extensions jpg/jpeg/png/webp; server chooses UUID filename beneath user UUID. Upload with `storage.from('profile-photos').upload(path,file)` (no upsert). Bucket private, 8 MiB max, image MIME allowlist. `remove_photo({p_slot})` → `{ok:true}`; removes reservation and queues physical object cleanup. Owners may delete storage objects, never rename/update them. Only reserved paths can be inserted; ≤9 reservations/account under a row lock. Storage SELECT allows owner, currently eligible discovery peers, or active match peer, with blocks/status checked. Use `createSignedUrl(path,60)`; previously issued signed URLs remain valid until expiry, so TTL must be short. Do not persist signed URLs. Storage API, not SQL, must remove physical files from cleanup queue.

## Billing, admin, deletion

`apply_billing_event({p_event_id,p_user,p_status,p_plan,p_customer,p_subscription,p_event_created,p_period_end})` → `{applied,reason}` (`applied|duplicate|stale`). Service role only after webhook signature verification; statuses `active|trialing|past_due|canceled|unpaid`, plans `free|plus|gold`. Only active/trialing and future period end grant entitlement. Unique event IDs and per-user serialization enforce idempotency and out-of-order protection; equal/older timestamps are ignored conservatively. Clients cannot set plans or billing identities. One billing provider stream per user; timestamps must come from authenticated provider events, not browser input.

`is_admin()` → `{is_admin:boolean,role:"admin"|"moderator"|null}` from current private role assignments. `billing_account({p_user})` → `{customer_id,subscription_id}|null`, service-only for the billing portal. `admin_metrics()` → `{profiles,active_profiles,matches,messages_count,open_reports,paid_subscriptions,new7d,active30d,estimated_mrr_cents,conversion_rate}`; never message text. `new7d` counts created profiles; `active30d` counts active accounts with recorded profile creation/update, decision, or sent message in 30 days (not login/page-view activity). Estimated MRR sums current configured monthly plan prices of unexpired active/trial subscriptions; conversion is paid subscription count divided by profile count, 0–1. `admin_reports()` → report objects (no message contents/DOB). `admin_moderate({p_target,p_action,p_reason})` (`suspend|restore|dismiss_reports`) → `{ok:true}`. `admin_save_plan({p_plan})` → plan object; fields `id,daily_likes,daily_superlikes,rewind,see_likes,monthly_boosts,boost_minutes,price_cents,currency,stripe_price_id,active`. `admin_save_city({p_city})` → city object; `id,name,country,latitude,longitude,active`; centroid precision ≤2 decimals. Seeded prices: Plus 990 and Gold 1990 EUR cents/month; `stripe_price_id` starts null and must be configured by an operator. Admin roles come only from private DB assignments by trusted operators: `moderator` may moderate/review reports; `admin` additionally configures plans/cities and metrics. No client writes to role assignments. Read active plans/cities directly via public tables.

`export_data()` → `{profile,decisions,matches,messages,blocks,reports,subscription,consents,photos}` containing only caller-owned data and messages they sent/received. `request_deletion()` → `{requested_at,purge_after}`; immediately hides user, stops chat, ends matches and queues photo deletion. `purge_deleted_accounts()` service-only → `{purged}` after configurable retention (default 30 days), removes personal SQL records and anonymizes retained abuse reports; leaves opaque Auth ID in `private.auth_deletion_queue` for parent's Auth Admin worker. Worker revokes sessions/deletes Auth account and acknowledges queue. `storage_cleanup_queue()` service-only → array of `{id,path}`; delete via Storage API then `ack_storage_cleanup({p_ids:[...]})`. `auth_deletion_queue()` service-only → array `{user_id,created_at}`; after Auth deletion `ack_auth_deletion({p_users:[...]})`. `retention_cleanup()` service-only removes expired reports (180 days), billing event dedup entries (400 days), and audit entries (365 days); schedule daily with a trusted worker. `private.retention_config` holds intervals. User-authored messages are removed when account is purged, including from peer history. Legal holds require operator policy before deployment.

## Execution and verification

Public RPCs are SECURITY INVOKER wrappers. Private operation-specific SECURITY DEFINER functions are necessary because direct table writes are denied; they have an empty search path, explicit identity/role checks and restricted EXECUTE grants. Private primitive helpers are not executable by clients. Every public/personal/private table has RLS; clients receive SELECT only where policies permit. Anonymous sign-ins are rejected. All functions have PUBLIC/anon execution revoked.

Run `node --test tests/database/*.test.mjs`. Tests execute the actual migration in PGlite PostgreSQL with minimal Auth/Storage schema fixtures and real SET ROLE/JWT claims. Docker is unavailable in this environment. PGlite cannot prove multi-connection race behavior or Supabase Storage HTTP enforcement; production verification must also run Supabase CLI reset/advisors and concurrent HTTP tests. Serialization and uniqueness are implemented in SQL, with structural assertions in tests.

## Auth hook and age assurance

`before_user_created(event jsonb)` follows the Supabase Before User Created hook response format. Local config enables it; hosted projects must enable the Database hook `public.before_user_created` in Auth settings **before opening signups**. Grant is exclusively `supabase_auth_admin`. Auth signup metadata must contain `dob: YYYY-MM-DD`; missing, malformed, future, under-18 and anonymous signups are rejected. Onboarding independently checks DOB even if a deployment omits the hook. This is self-declared age assurance, not identity verification; no verified ID provider is integrated. Do not render the DOB field in peer profile responses.

## Recurring billing cancellation outbox

`request_deletion()` atomically enqueues any known subscription in `private.billing_cancellations`. Later active billing events for a deleting profile also enqueue cancellation. Service-only `billing_cancellation_queue()` returns up to 100 `{id,user_id,customer_id,subscription_id,created_at}` records; cancel each subscription through Stripe, then call `ack_billing_cancellation({p_ids:uuid[]})`. Worker retries failures; perform idempotent provider cancellation. Records survive SQL purging and must be acknowledged only after provider success (or confirmed already canceled). Parent may attempt immediate cancellation, but must run this worker for durable recovery. Cancel subscriptions before deleting the Auth user. Deleting profiles cannot use ordinary RPCs, including `my_profile`; only `export_data` remains available until SQL purge. SQL purge tombstones prevent an old JWT from onboarding again while Auth deletion is pending.
